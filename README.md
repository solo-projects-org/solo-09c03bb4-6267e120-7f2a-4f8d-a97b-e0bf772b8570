# 住户能源调查 · 权重校准台账

固定样本 CSV → 按街道 / 住房类型精确校准户数 → 发布逐户权重；已交付街道可锁定，锁定值跨发布保留。
FastAPI + SQLite，单页服务端渲染，Docker Compose 启动。

## 快速开始

```bash
docker compose up --build -d
# 打开 http://localhost:8000
```

端口可用 `CALIBRATION_PORT=8080 docker compose up --build -d` 覆盖。

- 数据保存在命名卷 `calibration-data` 的 SQLite 文件中，`docker compose down`
  不会删除；`docker compose down -v` 才会连同数据一起清掉。
- 首次启动时用 `data/sample.csv`（固定样本，含样本号 / 街道 / 住房类型 / 正整数初始权重）
  灌入 200 户，现行权重＝初始权重。之后重启不会重复导入或覆盖。

不用 Docker 时：

```bash
python3 -m pip install -r requirements.txt
python3 -m uvicorn app.main:app --port 8000
```

测试：

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q
```

## 使用流程

1. **概览**：样本户数、初始 / 现行权重合计、已锁定街道数、成功发布次数。
2. **锁定街道**：下拉选择街道 → 锁定其**当前逐户权重**。发布前锁定即锁定初始值，
   发布后锁定即锁定最近一次发布的权重。重复锁定同一街道不会改变锁定值。
   锁定后，该街道的权重与合计在后续发布中保持不变，目标框显示为只读。
3. **设定目标户数**：分别填所有未锁定街道和目标住房类型的户数，点击「校准并发布」。
   - 两套目标必须**分别精确达标**。
   - 每户新权重为 **正整数且 ≤ 2 × 该户初始权重**（下限为 1）。
   - 锁定街道逐户取锁定值，因此它的合计也随之固定。
4. **发布**：所有约束同时可满足才会一次性写入全部逐户权重并留下发布记录；
   否则页面显示**一组极小冲突**（去掉其中任意一项，其余条件即可同时满足），
   且现行权重与发布记录都**不变**。

页面底部的「查看逐户现行权重」可展开核对每户初始值与现行值；重启服务后这些数据仍在。

## 核对两次发布之间的差异

台账页顶部的「核对两次发布之间的权重变化」进入 `/compare`（也可直接访问
`http://localhost:8000/compare`）：

1. 选择或直接输入两个发布号（新 → 旧均可，旧发布只要记录仍在即可查询）。
   不带参数时默认对比最近两次发布；只有一个发布时与自身对比，显示无差异。
2. **逐户差异**：按样本号排序列出权重发生变化的住户，显示街道、住房类型、旧值、新值和变化量。
   列表分页（默认每页 100 行，可设 1–500），按需从数据库读取。
3. **分组汇总**：分别按街道和住房类型给出「变化户数 / 变化住户合计（旧 → 新）」
   与「全部合计（旧 → 新）」，未变化的组也会列出。
4. 发布号不存在时返回 404 并提示；发布记录缺少完整逐户快照时返回 409 并提示。
5. 比较只读所选两个发布号的不可变快照，不读取现行权重，也不修改任何数据。
   因此核对期间产生的新发布不会改变已选结果，刷新或稍后重查结果一致。

### 快照与内存

- 每次成功发布在**同一事务**内写入发布记录和 `publication_weights`
  （每发布、每户一行），构成该次的完整逐户快照；发布失败则权重与快照一起回滚。
- 差异、计数与分组汇总全部由 SQLite 用 `publication_weights` 上的自连接完成，
  只把当前页的行取回 Python；不会把两份 20 万户快照或整个差异集载入内存。
  实测 20 万户、20 万户全部变化的极端情况下，比较进程峰值 RSS 约 21 MB。
- 本功能上线前已有的发布记录只有 `publications.weights_json` 整份 JSON，
  启动时会用 SQLite 的 `json_each` 一次性回填为 `publication_weights`（不经过 Python
  堆），之后按同样方式比较。回填失败只记录日志，不阻塞启动；该发布查询时给出快照不完整提示。


## 冲突提示语义

无解时返回的冲突集合由若干「条件」组成：

- `街道「X」目标户数 = N`：某未锁定街道的目标；
- `住房类型「T」目标户数 = N`：某住房类型的目标；
- `街道「X」锁定（…）`：某街道的锁定逐户权重。

该集合整体无解，而任意删去其中一条后剩余条件都有可行解，因此可以直接指出
"改这几个目标 / 放开某个锁定"这一最小修复方向。1 倍～2 倍初始权重、权重为正整数属于
不可放开的基础规则，不列入冲突集合。

## 实现要点

- `app/solver.py`：把问题写成街道—住房类型二分图上的整数运输问题。
  每户权重区间为整数 `[lower, upper]`，各街道与各类型的户数和为等式约束。
  约束矩阵是全幺模的，因此用带下界的最大流（Dinic + 下界平衡）即可判定
  整数可行性并直接得出整数解。冲突集合用贪心删除法求解极小不可行子集，
  每次删除都调用同一套流算法验证。
- `app/db.py`：SQLite 持久化。发布在单个 `BEGIN IMMEDIATE` 事务里完成
  锁定快照读取 → 求解 → 更新 → 写发布记录与逐户快照，失败即回滚，不会出现部分写入。
  跨发布核对同样在单个读事务内完成，保证所选两个发布的一致性视图。
- `app/main.py` 与 `app/templates/index.html`、`app/templates/compare.html`：
  FastAPI 路由 + 服务端渲染表单，发布成功 303 跳转并提示，冲突返回 409 并列出冲突项，
  输入错误返回 400；差异核对页为 `/compare`。
- 样本导入在启动时进行，表头接受中文列名；重复样本号、非正整数权重、
  缺失列都会在导入时报错。

## 已知限制

- 单进程 / 单用户场景设计：SQLite 以 `BEGIN IMMEDIATE` 串行化写操作，
  未做多租户或账号体系。
- 极小冲突集不唯一，返回的是按当前排序贪心删除得到的一组；它是有效的最小修复提示，
  但不保证是"唯一"或"条目数最少"的那一组。
- 目标户数的上限被限制在 10 亿（`MAX_TARGET`）以内，超出给出错误提示。
- 样本为固定 CSV，网页不提供增删样本的入口（符合"导入一份固定样本"的要求）。
- 差异核对页每次请求只展示一页逐户明细，不做 CSV 导出；发布号下拉最多列出最近
  1000 次，更早的发布号可直接输入查询。
- 若发布记录早于本功能且其 `weights_json` 回填失败，该发布只会给出"快照不完整"提示，
  不会影响其它发布或现行权重。
